# NewLife.Schneider 需求文档

> 版本：v1.0 | 日期：2026-07-22

本文档描述 NewLife.Schneider（施耐德 PLC 驱动库）的愿景、核心目标和功能方向。完成状态在[功能清单](功能清单.md)中追踪，详细设计在[架构设计](架构设计.md)中展开。

## 1. 背景与愿景

### 1.1 系统定位

NewLife.Schneider 是基于 Modbus TCP 协议的施耐德（Schneider Electric）PLC 通信驱动库，属于新生命 IoT 生态的驱动组件之一。它为上层 IoT 平台（如 ZeroIoT、IoTEdge）提供标准化的施耐德 PLC 设备接入能力，开发者通过统一的 `IDriver` / `INode` 接口即可完成设备连接、数据读写，无需关注 Modbus 协议细节。

### 1.2 愿景

成为 .NET 生态下最易用的施耐德 PLC 通信库——开箱即用、与 NewLife.IoT 生态无缝集成、驱动可自动发现、支持 Modbus TCP 全功能读写，让工业物联网应用开发像普通数据库访问一样简单。

## 2. 核心目标

| 编号 | 目标 | 所属层级 | 一句话描述 |
|------|------|----------|------------|
| DRV | 驱动核心 | 核心层 | 基于 Modbus TCP 实现施耐德 PLC 的连接管理与数据读写 |
| PRT | 协议扩展 | 扩展层 | 提供施耐德专用协议扩展（规划中） |
| TST | 测试验证 | 保障层 | 提供功能验证与集成测试 |

> 编码说明：新项目采用字母前缀方案（DRV/PRT/TST）。

## 3. 功能需求

### 3.1 DRV — 驱动核心

- **DRV-1 驱动入口（SchneiderDriver）**：实现 `ModbusTcpDriver` 的子类，标注 `[Driver("SchneiderPLC")]` 特性以支持驱动自动发现，驱动打开时自动初始化 Modbus 通道。
- **DRV-2 连接节点（SchneiderNode）**：实现 `INode` 接口，封装设备连接状态，持有驱动、设备、参数引用。
- **DRV-3 连接参数（SchneiderParameter）**：继承 `ModbusTcpParameter`，为施耐德 PLC 提供标准化 Modbus TCP 参数配置（主机地址、端口、功能码等）。

### 3.2 PRT — 协议扩展

- **PRT-1 施耐德专用协议**：针对施耐德 PLC 特有的协议扩展或优化实现（规划中，代码骨架已预留 `Protocols/` 目录）。

> 该模块目前仅有空目录，功能尚未实现。详见暂缓清单。

### 3.3 TST — 测试验证

- **TST-1 手动测试控制台**：提供控制台程序，可连接 Modbus TCP 服务端进行读写验证。

> 当前仅有手动测试程序，尚未建立自动化单元测试。

## 4. 🧊 暂缓清单

| 功能 | 暂缓理由 | 解冻前提 |
|------|----------|----------|
| PRT-1 施耐德专用协议 | 当前 Modbus TCP 已满足基本通信需求，专用协议需求不明确 | 出现 Modbus TCP 无法覆盖的施耐德特有协议需求 |
| 自动化单元测试 | 项目初期以功能验证为主 | 驱动核心功能稳定后补充单元测试覆盖 |
| 施耐德特有数据类型支持 | 基础类型读写已通过 Modbus 实现 | 用户反馈需要更高级的数据类型映射 |

## 5. 不做什么

- 不实现 Modbus TCP 以外的传输层协议（如串口 RTU、ASCII），这些由 NewLife.Modbus 基础库提供。
- 不实现设备管理、拓扑发现等 IoT 平台层功能，这些由上层平台（ZeroIoT/IoTEdge）负责。
- 不提供 Web 管理界面，这是一个纯驱动类库。
